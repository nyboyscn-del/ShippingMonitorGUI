# ShippingMonitorGUI 异机摄像头录像测试说明

## 1. 测试目的

使用另一台电脑和另一只摄像头，验证录像清晰度、运动流畅度、时长一致性、重复帧比例和摄像头兼容性。

## 2. 测试前准备

1. 推荐先把整个 `ShippingMonitorGUI_CameraTest` 文件夹复制到测试电脑的本地磁盘，再运行 `ShippingMonitorGUI.exe`。直接从移动盘录像可能把 USB 写入速度引入测试结果。
2. 摄像头直接连接电脑 USB 接口，尽量不要经过无供电 USB Hub。
3. 关闭 Windows 相机、微信、浏览器、OBS 等可能占用摄像头的软件。
4. 保持正常工作现场的灯光和摄像头安装位置。
5. 准备一个带有小字、条码和边缘细节的快递面单或测试纸张。

## 4. 标准录像内容

每个场景使用不同的 12 位纯数字测试单号。输入单号并按回车后开始录像，达到规定时间后输入下一单号切换录像。

### 场景 A：静态清晰度，30 秒

- 测试单号：`990000000001`
- 将面单放在正常打包位置，保持静止。
- 画面中应包含小字、条码、包裹边缘和背景。
- 前 10 秒保持不动；中间 10 秒用手指指向面单不同位置；最后 10 秒再次保持不动。
- 观察自动对焦是否反复拉风箱、文字是否清楚、亮度是否稳定。

### 场景 B：慢速运动，30 秒

- 测试单号：`990000000002`
- 手持包裹在画面中从左到右、再从右到左缓慢移动。
- 每次横向移动约 4 秒，共重复 5 次。
- 包裹尽量保持正对摄像头，观察运动是否连续、有无明显跳帧或拖影。

### 场景 C：正常打包操作，60 秒

- 测试单号：`990000000003`
- 按真实工作节奏完成取件、翻面、贴单、封箱或扫码动作。
- 动作不需要刻意放慢。
- 该段是最重要的业务场景，用于判断实际使用体验。

### 场景 D：快速运动，30 秒

- 测试单号：`990000000004`
- 快速移动手、胶带和包裹，但不要故意晃动摄像头。
- 交替进行快速动作和停止动作，便于区分运动模糊与失焦。

### 场景 E：弱光测试，可选 30 秒

- 测试单号：`990000000005`
- 在现场可能出现的较暗照明条件下重复静态面单和慢速移动。
- 不要在完全黑暗环境测试。

## 5. 测试结束

1. 点击停止录像并正常退出程序。
2. 随机播放每段 AVI，确认可以打开且结尾完整。
3. 不要重命名录像文件，不要转码，不要通过聊天软件压缩发送。
4. 将以下内容原样复制回 F 盘的 `RETURN_FOR_ANALYSIS` 文件夹：
   - 整个 `recordings` 文件夹
   - 整个 `logs` 文件夹
   - 本说明文件填写后的副本，或环境记录的照片/文本
5. 不需要复制 `license.json`、`license_state.json`、`trial_state.json` 或任何授权文件。

## 6. 技术判定参考

- 分辨率：优先达到 `1920x1080`。
- 录像时长误差：不超过 0.5 秒或总时长的 2%。
- `duplicate_ratio`：低于 5% 为优秀，5%-15% 可接受，高于 15% 需要继续诊断。
- `skipped_capture_frames`：优先为 0；持续增长说明处理速度或 USB 采集存在瓶颈。
- `avg_processing_ms` / `avg_writer_ms`：分别是单帧校正、水印处理和编码写盘的平均耗时；两者之和若接近或超过一帧间隔（16 FPS 约为 62.5 ms），录像线程可能跟不上摄像头。
- `max_writer_ms` / `max_capture_age_ms`：分别用于定位偶发写盘停顿和录像线程拿到旧帧的情况。
- 静态场景：面单小字可辨认，自动对焦不应持续来回变化。
- 慢速运动：移动连续，不应出现明显周期性停顿。
- 正常操作：动作和时间顺序完整，录像末尾不缺失。

## 7. 返回分析重点

带回录像后将统一检查：

- 摄像头 backend、输入 FOURCC、实测采集 FPS 和 writer FPS
- 总帧数、真实帧、重复帧、跳过采集帧和真实处理 FPS
- 单帧处理、编码写盘耗时，以及最大采集帧等待时间
- AVI 声明时长与实际录像时长
- 静态清晰度、自动对焦稳定性、运动模糊和周期性卡顿
- 是否需要针对该摄像头调整分辨率、FPS、对焦或曝光策略
